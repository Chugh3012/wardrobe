- [ ] **Status:** Open

## Description

Create a GitHub Actions workflow (`.github/workflows/pr-validation.yml`) that runs on every pull request to `main` and validates the full app — backend unit tests, frontend build, and Playwright E2E tests with mocked API responses — **without requiring any Azure services or credentials**. This gives Copilot-generated PRs and human PRs a quality gate that catches UI regressions, broken navigation, rendering issues, and backend logic errors before merge.

Currently, the repo has three deploy-oriented workflows (`deploy-backend.yml`, `deploy-frontend.yml`, `provision-infra.yml`) but **no unified PR test workflow** that exercises the full stack with mocked services. The existing Playwright E2E suite (`e2e/tests/ui-pages.spec.ts`) already mocks `/.auth/me` and all API routes via `mockApis(page)`, and the `playwright.config.ts` `webServer` block automatically builds the frontend and starts a Vite preview server. This issue wires those existing pieces into a CI workflow.

## What This Workflow Runs (in order)

1. **Backend unit tests** — `cd backend && npm ci && npm test` (199 Vitest tests across 18 files)
2. **Frontend build** — `cd frontend && npm ci && npm run build` (validates TypeScript compilation + Vite build)
3. **Playwright E2E (mocked)** — `cd e2e && npm ci && npx playwright install --with-deps && npx playwright test --project=ui-desktop --project=ui-mobile`
   - The `webServer` in `playwright.config.ts` handles building the frontend and starting the Vite preview server on port 5173
   - UI tests mock `/.auth/me` → valid `clientPrincipal` (simulates authenticated user)
   - API routes (`/api/garments`, `/api/stats/summary`, `/api/wear/predict`, `/api/wear/confirm`, `/api/images/sas`) are intercepted via Playwright route mocking with test fixtures
   - `serviceWorkers: 'block'` is already configured in `playwright.config.ts` for reliable route mocking
   - **Does NOT require** `SWA_URL`, `FUNC_URL`, or any Azure credentials

## Proposed Workflow File: `.github/workflows/pr-validation.yml`

```yaml
name: PR Validation

on:
  pull_request:
    branches: [main]

permissions:
  contents: read
  pull-requests: write

jobs:
  backend-tests:
    name: Backend Unit Tests
    runs-on: ubuntu-latest
    steps:
      - uses: actions/checkout@v4
      - uses: actions/setup-node@v4
        with:
          node-version: '20'
          cache: 'npm'
          cache-dependency-path: backend/package-lock.json
      - run: cd backend && npm ci
      - run: cd backend && npm test

  frontend-build:
    name: Frontend Build
    runs-on: ubuntu-latest
    steps:
      - uses: actions/checkout@v4
      - uses: actions/setup-node@v4
        with:
          node-version: '20'
          cache: 'npm'
          cache-dependency-path: frontend/package-lock.json
      - run: cd frontend && npm ci
      - run: cd frontend && npm run build

  e2e-mocked:
    name: E2E Tests (Mocked APIs)
    runs-on: ubuntu-latest
    needs: [backend-tests, frontend-build]
    steps:
      - uses: actions/checkout@v4
      - uses: actions/setup-node@v4
        with:
          node-version: '20'
      - run: cd frontend && npm ci
      - run: cd e2e && npm ci
      - run: cd e2e && npx playwright install --with-deps
      - run: cd e2e && npx playwright test --project=ui-desktop --project=ui-mobile
        env:
          CI: true
      - name: Upload Playwright report
        if: always()
        uses: actions/upload-artifact@v4
        with:
          name: playwright-report
          path: e2e/playwright-report/
          retention-days: 7
```

## Acceptance Criteria

- [ ] `.github/workflows/pr-validation.yml` exists and triggers on `pull_request` to `main`.
- [ ] Backend unit tests job runs `npm test` in `backend/` and fails the PR if any test fails.
- [ ] Frontend build job runs `npm run build` in `frontend/` and fails the PR if TypeScript/Vite build fails.
- [ ] Playwright E2E job runs `ui-desktop` and `ui-mobile` projects with mocked APIs (no Azure credentials needed).
- [ ] Playwright HTML report is uploaded as a GitHub Actions artifact on every run (pass or fail).
- [ ] The workflow completes in under 5 minutes for a typical PR.
- [ ] All three jobs are required to pass before a PR can be merged (configure as branch protection rule).
- [ ] `SWA_URL` and `FUNC_URL` are **not** required — the E2E tests use the local Vite preview server + route mocking only.
- [ ] The `azure-resources` and `api-endpoints` Playwright projects are **excluded** from this workflow (they require live Azure credentials and run post-deploy).
